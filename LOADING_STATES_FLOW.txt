Requirement 3: Ciclo de Vida y Hooks
────────────────────────────────────────────────────────────────────────────
"The system shall renderizar estados de carga granulares (ej. 'Extrayendo
DOM...', 'Esperando auditoría...') en la Task List UI mientras espera la
respuesta del backend."

✅ CUMPLIDO:
   • 3 estados granulares distintos implementados
   • Mensajes descriptivos y específicos para cada fase
   • Spinner SVG animado visible durante todas las operaciones
   • Limpieza garantizada mediante bloque finally
   • Logging completo para debugging

║                          ESCENARIOS DE PRUEBA                                 ║
╚═══════════════════════════════════════════════════════════════════════════════╝

1. ESCENARIO EXITOSO CON ERRORES
   ─────────────────────────────────────────────────────────────────────────
   Pasos:
   1. Seleccionar elemento con errores de accesibilidad
   2. Click en "Auditar componente seleccionado"
   3. Observar secuencia de estados:
      → "Extrayendo DOM..."
      → "Esperando auditoría..."
      → "Procesando 3 resultado(s)..." (ejemplo)
   4. Ver lista de tareas renderizada
   
   Resultado esperado: ✅ Estados visibles, spinner desaparece, tareas mostradas

2. ESCENARIO SIN ELEMENTO SELECCIONADO
   ─────────────────────────────────────────────────────────────────────────
   Pasos:
   1. NO seleccionar ningún elemento en el inspector
   2. Click en "Auditar componente seleccionado"
   3. Observar estado: "Extrayendo DOM..."
   4. Ver alerta de error
   
   Resultado esperado: ✅ Spinner desaparece, alerta visible, botón habilitado

3. ESCENARIO DE TIMEOUT
   ─────────────────────────────────────────────────────────────────────────
   Pasos:
   1. Simular backend lento o sin conexión
   2. Click en "Auditar componente seleccionado"
   3. Observar estados por ~10 segundos
   4. Ver mensaje de timeout
   
   Resultado esperado: ✅ Spinner desaparece después de timeout, alerta visible
